> 이 파일이 부정 사용 검증 단계의 **단일 정본**(설계 + 실행 지시)이다. 단계 간 계약의 정본은 [docs/interface-spec.md](../../docs/interface-spec.md), 감지 기준의 정본은 [docs/fraud-rules.md](../../docs/fraud-rules.md). 담당·상태·테스트 방법·협의 메모는 [verify3/README.md](../../verify3/README.md). 동작을 바꿀 땐 이 파일을 먼저 고치고(문서 먼저, 구현 나중), 단계 간 약속이 걸리면 interface-spec을 담당자 합의로 고친다.

## 역할

가공된 거래 표의 **법인결제 행**을 법인카드 부정 사용 관점에서 점검한다 (분류 관점은 분류 검증, 기간·금액 관점은 기간·금액 검증 담당). 분류/기간·금액 검증과 같은 입력을 동시에 받는 병렬 구조이며, **부정 사용 감지 토글을 켠 실행에서만 호출된다** (기본 꺼짐). 부정 사용을 단정하지 않는다 — 기준에 걸린 건은 `확인 요청`으로 표시해 사용자 판단(중간 확인·확인 필요 목록)으로 넘기고, 어떤 행도 고치거나 지우지 않는다.

## 입출력

- 입력: `refine/result.csv`의 가공된 거래 표 (분류/기간·금액 검증과 동일 입력), **CSV**. 스키마는 interface-spec.md "거래 표 스키마 (확정 v1)"
- 실행 파라미터: 대상 월(`YYYY-MM`) — 지휘가 호출 시 전달한다 (interface-spec.md §실행 파라미터). 이 단계 자체가 토글 켠 실행에서만 불리므로 토글 값은 별도로 받지 않는다
- 출력: 거래 행별 통과/확인 요청 결과 + 사유, CSV로 `verify3/result.csv`에 저장. 모양(확정 — interface-spec.md 부정 사용 검증 행): 입력 행 뒤에 `verify3_result`(`통과`/`확인 요청`)·`verify3_reason`(사유, 통과면 빈칸 또는 참고 메모) 두 열을 덧붙인다. 행을 지우거나 순서를 바꾸지 않고, 행 대조 키는 `transaction_id`.

## 처리 절차

1. `refine/result.csv`에서 가공된 거래 표를 로드한다.
2. `결제구분`이 `법인결제`인 행만 판정 대상으로 삼는다. `개인결제` 행은 판정 없이 `통과`(사유 빈칸)로 둔다.
3. 대상 행마다 [docs/fraud-rules.md](../../docs/fraud-rules.md)의 감지 기준(F1 - F6)을 전부 적용한다. 여러 기준이 걸리면 사유를 모두 기록한다.
4. fraud-rules.md의 판정 규칙(스코어링)대로 `통과`/`확인 요청`을 정한다 — 강 신호 1개 또는 약·중 신호 2개 이상이면 `확인 요청`.
5. 결과 표를 `verify3/result.csv`로 저장한다.
6. 단계 결과 보고(JSON envelope — interface-spec.md "단계 결과 보고" 규격)를 만들어 지휘에게 반환한다. `확인 요청` 건은 `flags[].type` = `확인 요청`으로 싣는다.

## 판단 기준

기준의 정본은 [docs/fraud-rules.md](../../docs/fraud-rules.md)다 — **실행 시점의 파일을 매번 읽고 그대로 적용한다.** 여기서 재정의하지 않는다.

- AI 판단 / 일반 코드 구분: CSV 읽기/쓰기·주말/시각 판정·키워드 포함 대조·동일 가맹점 건수 집계·금액 임계 비교·스코어링·사유 템플릿 채움은 일반 코드로 처리해 판정이 흔들리지 않게 하고(실행 코드 `verify3/verify3.py`), 키워드 오탐 문맥 판단(예: "바르다김선생"은 F3 아님)·개인성 소비 의심(F4) 추론에만 AI 판단을 쓴다 — AI 호출이 불가한 환경이면 F3는 키워드 대조 결과를 그대로 쓰고 F4는 건너뛴다(판정을 지어내지 않는다)
- 부정 사용 여부를 단정하는 표현을 쓰지 않는다 — 사유는 "의심"·"확인 필요" 수준으로 쓴다 (템플릿은 fraud-rules.md)
- 분류/기간·금액 검증의 관점(분류·기간·금액)은 건드리지 않는다

## 오류·예외 처리

- 입력 표가 없거나 비어 있으면 → `status: "empty"`, `message: "검증 대상 없음"` (재시도 없음).
- 법인결제 행이 0건이면 → 전 행 `통과`로 산출하고 `message`에 "법인결제 행 없음 — 판정 대상 없음"을 남긴다.
- 필수 컬럼(`transaction_id`·`날짜`·`금액`·`결제처`·`결제구분`)이 누락되면 → 검증 진행하지 않고 `status: "failed"`로 즉시 보고하고, `message`에 누락된 컬럼을 명시한다.
- 개별 행 판단이 불가능하면(예: 날짜 형식 깨짐) 임의로 통과 처리하지 않고 `확인 요청`·사유 `"판단 불가 (형식 오류)"`로 남긴다.

## 알려진 블로커 (임의로 채우지 말 것)

- 결제 시각 데이터 부재 — 거래 표 스키마에 시각 컬럼이 없어 F2(심야)는 비고·원문에 시각이 남은 행에만 적용된다. 시각 컬럼 추가는 별도 interface-spec 개정 사항.
- 임직원 휴가일·출장일 대조(휴가 중 결제 감지)는 달력 데이터가 없어 이번 범위에서 제외 — 필요 시 별도 논의.

docs/interface-spec.md·docs/fraud-rules.md가 갱신되면 이 문서도 함께 갱신한다.
