# 수집 받는 재료 견본 (input-sample)

> collect가 받는 두 원천 모두 `sample_data/`에 더미로 준비돼 있다 — 년월 폴더(`sample_data/<YYYY-MM>/`) 안에 그 달의 카드사 Excel/CSV와 영수증 이미지·결제 문자 캡처(OCR 대상)가 함께 들어 있다.
>
> **실제 처리 대상은 `sample_data/` 아래 원본 파일 전체**다. 이 문서의 표·예시는 컬럼이 어떻게 생겼는지 보여주는 견본일 뿐, 그 자체가 처리 재료는 아니다 — 실행할 때는 이 문서가 아니라 `sample_data/` 원본을 읽는다.
>
> 카드사마다, 그리고 법인카드냐 개인카드냐에 따라 컬럼 구성이 달라진다 — 새 카드사·법인카드 샘플이 추가되면 이 문서에 서식별로 나란히 추가한다. [`collect.md`](../.claude/agents/collect.md) "하는 단계 1"의 정규화 규칙이 서식마다 다른 컬럼을 표준 필드로 흡수하는 지점이다.
>
> **더미는 일부러 지저분하다** — 인코딩·서식·데이터 품질 함정이 파일마다 심겨 있다. 어떤 파일에 어떤 함정이 있고 기대 동작이 무엇인지는 [`sample_data/README.md`](../sample_data/README.md)가 정본이다 (이 문서는 서식 설명만 담는다).

## 1. 카드사 Excel/CSV — 하나카드 이용내역서 (개인카드 서식 예시)

`sample_data/2026-02/2026-02_하나카드_이용내역서.csv`에서 그대로 가져온 값:

| 컬럼 | 설명 | 예시 |
|---|---|---|
| 이용일자 | 결제일 (할부는 최초 구매일 그대로 유지) | 2026-02-02 |
| 이용가맹점 | 가맹점명 (PG사 표기 그대로 — 정규화는 가공 단계 몫) | 쿠팡 |
| 이용금액 | 거래 총액 (할부는 매달 같은 값 반복) | 67,302 |
| 할부기간 | `일시불` 또는 `N개월` | 일시불 |
| 회차 | 할부일 때만 `N/전체` (일시불은 `-`) | - |
| 원금 | 이번 청구에 포함된 원금 | 67,302 |
| 수수료 | 이번 청구에 포함된 할부 수수료 (일시불은 0) | 0 |
| 이용혜택 | 적용된 혜택명, 없으면 `없음` | 포인트 적립 |
| 혜택금액 | 혜택 금액, 없으면 0 | 1,346 |
| 결제후잔액 | 할부 잔여 원금 (일시불은 0) | 0 |
| 포인트 | 적립 포인트 | 337 |

원본 예시 2행:

```csv
이용일자,이용가맹점,이용금액,할부기간,회차,원금,수수료,이용혜택,혜택금액,결제후잔액,포인트
2026-02-02,쿠팡,67302,일시불,-,67302,0,포인트 적립,1346,0,337
2026-02-03,CGV,15674,일시불,-,15674,0,없음,0,0,78
```

할부 거래는 [stub.md](stub.md)의 "할부 거래" 예시를 참고 (하이마트 냉장고, 2026-02-10 구매 · 6개월 할부).

## 2. 카드사 Excel/CSV — 신한법인카드 승인내역 (법인카드 서식)

각 년월 폴더의 `<YYYY-MM>_신한법인카드_승인내역.csv` (예: `sample_data/2026-08/`). UTF-8, 헤더 1행 + 데이터 행.

```csv
승인일시,카드번호,가맹점명,업종,승인금액,공급가액,부가세,통화,해외이용금액,승인번호,사용자,취소여부
2026-07-02 12:34:56,9410,모두의주차장 강남점,주차장,12000,10909,1091,KRW,,30711022,김규은,N
2026-07-09 19:22:05,9410,APPLE.COM/BILL,디지털콘텐츠,55890,,,USD,39.99,30755401,이지은,N
```

하나카드 서식과 다른 점: 날짜에 시각 포함 · 공급가액/부가세 분리 · 해외결제는 `통화`+`해외이용금액` 컬럼(원화 환산액은 `승인금액`) · 취소 거래는 같은 승인번호로 `취소여부 Y` 행이 별도로 붙음 · `사용자`(직원명) 컬럼 존재 · 혜택/포인트 컬럼 없음.

## 3. 카드사 Excel/CSV — KB국민카드 이용대금명세서 (개인카드 서식)

각 년월 폴더의 `<YYYY-MM>_KB국민카드_이용대금명세서.csv`. **cp949 인코딩**, 표 위에 머리말 4줄·표 아래에 합계/안내문 행이 붙는 명세서 서식.

```csv
이용일,이용하신곳,이용카드,이용금액,할부,적립예정포인트
2026.07.03,"스타벅스 역삼점",5678,"12,300",일시불,123
```

날짜는 점 표기(`2026.07.03`), 금액은 따옴표+쉼표 문자열, 해외결제는 별도 컬럼 없이 가맹점명에 `AMAZON.COM 29.99 USD`처럼 섞임.

## 4. 카드사 Excel/CSV — 롯데카드 이용내역 (서식 불명·저품질)

각 년월 폴더의 `<YYYY-MM>_롯데카드_이용내역.csv`. UTF-8, 컬럼은 `이용일자,가맹점,금액,구분,메모` 5개뿐이지만 행마다 날짜·금액 표기가 제각각이고 결측·중복·컬럼 어긋남이 섞여 있다. 서식 규칙을 신뢰할 수 없는 원천의 대표 케이스.

## 5. 그 외 파일 케이스

- 각 년월 폴더의 `<YYYY-MM>_우리카드_이용내역.csv` — 헤더만 있고 거래 행이 없는 빈 파일
- `sample_data/misc/` — 카드 거래가 아닌 파일 (전기요금 안내문 txt, 특정 월에 종속되지 않아 년월 폴더 밖에 둔다)

## 6. 영수증 이미지·결제 문자 캡처 (OCR 대상)

- 형식: Google Drive·Google Photos에 업로드된 이미지 파일 (사진·스크린샷)
- 견본: 각 년월 폴더의 PNG (예: `sample_data/2026-07/` 6장, `sample_data/2026-06/` 7장) — 정상 영수증·정상 결제 문자 외에 흐린 영수증, 금액이 잘린 영수증, 결제 문자를 흉내 낸 스미싱 광고, 영수증이 아닌 일반 사진, 카드 정보 없는 수기 간이영수증이 섞여 있다 (파일별 성격·기대 동작은 [`sample_data/README.md`](../sample_data/README.md) §2·§3)
- 추출 대상 정보: 거래일 · 금액 · 결제처 · 결제수단 (`collect.md` "하는 단계" 참고)
