# 가공 (refine) — 이 칸의 약속

> 담당: 조영진 · 결제처 정규화 + 카테고리 부여 · 상태: 초안
> 계약의 정본은 [인터페이스 정의서](../docs/interface-spec.md), 단계 문서(설계+실행 지시의 단일 정본)는 [.claude/agents/refine.md](../.claude/agents/refine.md).

## 하는 일

수집(collect)이 만든 표준 거래 내역표(CSV)를 받아, `결제처`의 PG사 표기를 실제 가맹점명으로 정규화하고 각 거래에 [categories.md](../docs/categories.md) 체계의 `카테고리`를 채운다. 파이프라인의 두 번째 단계이고, 결과는 분류 검증([verify1/](../verify1/))·기간·금액 검증([verify2/](../verify2/))가 **같은 것을 동시에** 받는다.

## 받는 것 / 내놓는 것

| | 내용 | 모양 |
|---|---|---|
| 받는 것 | 표준 형식의 거래 내역표 | CSV — [input-sample.md](input-sample.md) (수집 산출물 [collect/result.csv](../collect/result.csv)) |
| 내놓는 것 | 가맹점·카테고리가 붙은 거래 표 | CSV — [stub.md](stub.md) |

받은 표의 행을 지우거나 순서를 바꾸지 않는다. `결제처`를 정규화하고, 거래 표 스키마의 `카테고리` 열(수집 산출물엔 비어 있음)을 채워서 내놓는다.

## 이 칸의 파일

| 파일 | 무엇 |
|---|---|
| `README.md` | 이 문서 — 칸의 약속 |
| `input-sample.md` | 받는 재료 견본 (가짜 데이터) |
| `stub.md` | 산출물 모양 견본 (가짜 데이터) |
| `result.csv` | 진짜 산출물 — 실행하면 생김. **커밋하지 않는다** |
| `refine.py` | 실행 스크립트 — 알려진 가맹점/PG 매핑 규칙(일반 코드 몫)만 적용하고, 매핑 밖 건은 `확인 필요`로 남긴다. 파이프라인의 가공 실행은 현재 지휘의 API 단발 호출(단계 문서 프롬프트) 방식이고 이 스크립트는 로컬 확인용 |
| `screen.html` | 연습용 화면 — 미리 넣어둔 견본 결과를 보여준다 (실제 처리 없음) |

결과를 만드는 데 코드가 필요하면 그 코드도 이 칸 폴더 안에 둔다. 칸 폴더를 옮기지 않고, 기존 파일을 지우지 않는다. 새 산출물은 견본 옆에 만든다.

## 정규화·분류 규칙 (요약)

상세는 [단계 문서](../.claude/agents/refine.md)에 있다.

- **결제처 정규화** — PG사·플랫폼 표기 뒤의 실제 가맹점이 어디인지 판단해 가맹점명으로 바꾼다. PG 표기라 실제 가맹점을 특정할 수 없으면 `결제처`는 원문 그대로 두고 `확인 필요`로 남긴다
- **카테고리 부여** — 정규화된 가맹점명과 `구매항목`(영수증 구매 물품)·`비고`의 부가 정보를 근거로 [categories.md](../docs/categories.md)의 카테고리를 채운다. 명칭은 categories.md에 정의된 것을 그대로 쓴다. `구매항목`이 비어 있으면 `결제처`·`비고`만으로 판단한다
- **애매하면 임의 배정 금지** — 가맹점 식별·분류가 불가한 건은 `카테고리`에 `확인 필요`로 표시하고 버리지 않는다 (인터페이스 정의서 가공 "못 할 때", [categories.md](../docs/categories.md) 운영 규칙)
- 처리할 행이 0건이면 `"확인 대상 없음"`으로 표시한다. 빈 파일을 조용히 내놓지 않는다

## 지켜야 할 것

- **실데이터를 커밋하지 않는다.** 견본은 [sample_data/](../sample_data/) 기반 가짜 데이터로만 만든다 (개인 금융정보)
- **문서 먼저, 구현 나중.** 동작을 바꾸려면 [단계 문서](../.claude/agents/refine.md)를 먼저 고친다. 단계 간 약속이 걸리면 [인터페이스 정의서](../docs/interface-spec.md)를 담당자 합의로 고친다

## 테스트 방법

수집 산출물 견본(가짜 데이터 기반)을 입력으로 삼아 테스트한다 (실데이터 사용 금지 — AGENTS.md §8). 견본 파일(`input-sample.md`·`stub.md`)도 가짜 데이터 기준으로 만든다.

| 샘플 입력 | 기대 출력 |
|---|---|
| PG사 표기가 붙은 결제처 행 (예: `NHN KCP/실가맹점명`) | `결제처`가 실제 가맹점명으로 정규화된 행 |
| 명확히 분류 가능한 거래 (예: 카페 결제) | `카테고리`가 [categories.md](../docs/categories.md) 체계로 채워진 행 |
| `구매항목`이 있는 거래 (예: 배달의민족 / 부대찌개) | `구매항목`을 근거로 `식대`로 분류 |
| 가맹점 식별·분류가 애매한 거래 (예: PG 표기 + `구매항목` 빈 값) | `확인 필요` 표시, 임의 카테고리 배정하지 않음 |
| 스키마 보존 확인 | 입력 대비 컬럼 추가·삭제 없이 `결제처`·`카테고리`만 갱신 |
