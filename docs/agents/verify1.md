# 검증 1 에이전트 설계

> 담당: 김윤덕 · 상태: 초안
> 입출력의 정본은 [인터페이스 정의서](../interface-spec.md) — 여기에는 요약과 링크만 두고, 상세 스키마를 재정의하지 않는다.

## 1. 역할

가공(refine)이 붙인 카테고리가 팀이 정한 회계 계정과목 체계에 맞는지 항목별로 판정한다. 검증 2와 같은 입력을 동시에 받는 병렬 구조이며, 이 단계는 **분류 관점**만 본다.

## 2. 입출력 요약

- 받는 것: 회계 계정과목에 맞게 카테고리가 부여된 카드 사용내역 **CSV 파일** (→ 상세는 [인터페이스 정의서](../interface-spec.md) "가공" 행과 "거래 표 스키마")
- 내놓는 것: 항목마다 통과/반려와 이유 한 줄이 붙은 CSV 파일 — `verify1/result.csv` (→ 상동 "검증 1" 행)

## 3. 내부 처리 절차

1. **기준 읽기** — [categories.md](../categories.md)에서 정의된 카테고리 명칭 목록을 읽어 판정 기준을 세운다
2. **입력 열기** — 가공 산출물을 읽는다. 없거나 열리지 않으면 5장의 오류 처리로 넘어간다
3. **대상 확인** — 검증할 행이 하나도 없으면 "확인 대상 없음"으로 마무리한다 (5장)
4. **행별 판정** — 각 행의 카테고리 명칭을 기준 목록과 대조해 통과/반려를 정하고, 반려면 이유 한 줄을 만든다
5. **결과 파일 작성** — 입력 행을 그대로 두고 판정 열·이유 열을 더해 `verify1/result.csv`로 쓴다
6. **결과 보고** — 처리 건수와 반려 목록을 담은 요약 JSON을 지휘에게 넘긴다 (형식은 인터페이스 정의서 "단계 결과 보고")

## 4. 판단 규칙

- 판단할 것: 각 거래에 부여된 **카테고리 명칭이 정해진 회계 계정과목 체계에 있는가**
- 판단 기준: [categories.md](../categories.md)에 정의된 명칭과 **정확히 일치**하면 통과, 다르면 반려. 표기만 다른 경우(띄어쓰기·유사어)도 반려로 보고, 이유 줄에 어느 카테고리로 보이는지 함께 적는다
- 애매할 때 참조: [categories.md](../categories.md)가 정본. 문서 상태가 "제안"이지만 **곧 확정될 예정이라, 확정 전에도 현재 적힌 체계를 그대로 적용한다**. 그래도 갈리는 항목은 임의로 정하지 않고 8장 "막힌 점"에 올려 팀과 확정한다
- 범위 밖: 명칭이 체계에 있으면 통과로 본다. **그 거래에 그 카테고리가 어울리는지**까지 다투는 건 이 단계가 정하지 않는다 — 명백히 어긋나 보이면 반려 대신 이유 줄에 의견을 남긴다. 기간·금액 관점은 검증 2 몫이다
- 핵심 지시 (이 에이전트에게 시키는 말의 요지): "카테고리 명칭이 정해진 체계와 다르면 반려하고, 왜 다른지 한 줄로 적어라. 판정할 수 없는 항목도 버리지 말고 남겨라"
- AI 판단이 필요한 곳 / 일반 코드로 처리할 곳:
  - 일반 코드 — 명칭 문자열 대조, 결과 열 추가, 파일 입출력, 건수 집계
  - AI 판단 — 반려 사유 한 줄 작성, 어긋난 명칭이 어느 카테고리를 의도한 것인지 추정

## 5. 오류·예외 처리

- **검증할 항목 없음** — 결과 파일에 `"확인 대상 없음"`으로 표시하고 결과 보고에도 같은 뜻을 담는다. 빈 파일을 조용히 내놓지 않는다
- **입력 파일 없음·열기 실패** — 추측해서 만들어내지 않는다. 실패 사실과 사유를 그대로 보고한다
- **판정 불가 항목** — 버리지 않는다. 반려로 두고 이유 줄에 판정 불가 사유를 적는다
- 실패를 조용히 삼키지 않는다 (공통 규칙 AGENTS_COM.md §4)

## 6. 사용 도구·의존성

- 언어: Python (프로젝트 공통 — 버전·패키지 매니저 미정)
- 입출력 형식이 CSV로 정해져([인터페이스 정의서](../interface-spec.md) "다음 단계" 참고) 이 단계는 표준 `csv` 모듈이나 `pandas`면 충분하다 — 엑셀 라이브러리 결정은 이제 통합(`merge`)의 최종 산출물 생성에만 해당된다
- 모델: 반려 사유 작성·명칭 추정에만 사용. 명칭 대조 자체는 코드로 처리해 판정이 흔들리지 않게 한다

## 7. 테스트 방법

`sample_data/`의 가짜 데이터로만 테스트한다 (실데이터 사용 금지 — AGENTS.md §8).

| 샘플 입력 | 기대 출력 |
|---|---|
| 모든 행의 카테고리가 체계에 있는 표 | 전 행 통과, 반려 0건 |
| 체계에 없는 명칭(예: "식대")이 섞인 표 | 해당 행만 반려 + 추정 카테고리("식비")가 이유에 포함 |
| 카테고리 칸이 빈 행이 섞인 표 | 해당 행 반려 + 판정 불가 사유 |
| 데이터 행이 0건인 표 | "확인 대상 없음" 표시, 빈 파일 아님 |

견본 파일(`verify1/input-sample.md`·`verify1/stub.md`)도 이 가짜 데이터 기준으로 만든다.
