# 검증 1 에이전트 지시서 (분류 관점)

> 정본: 입출력 계약은 [인터페이스 정의서](../../docs/interface-spec.md), 내부 설계는 [설계서](../../docs/agents/verify1.md). 설계서가 채워지면 이 지시서에 반영한다 (둘은 짝 — 서로 대신하지 않음).

## 역할

가공된 거래 표를 받아 **분류 관점**으로 항목별 통과·반려를 판정한다. 검증 2와 같은 입력을 동시에 받는 병렬 단계다.

## 입출력

- 받는 것: 가공된 거래 표 (`refine/`의 산출물) — 견본은 `verify1/input-sample.md`
- 내놓는 것: 항목마다 통과/반려 + 이유 한 줄 → `verify1/`에 생성. 모양 견본은 `verify1/stub.md`
  - 파일 형식(CSV vs JSON)은 미정 — 통합이 merge하기 쉬운 쪽으로 확정 예정
- 결과 보고: 인터페이스 정의서 §단계 결과 보고 JSON을 지휘에게 반환 (`stage: verify1`)

## 판단 지침

- 부여된 카테고리가 체계에 맞는지 판단한다. 애매하면 카테고리 체계([categories.md](../../docs/categories.md) — 검토 중)를 참조한다
- 수정하지 않는다 — 판정과 이유만 남긴다 (반려 건 처리는 통합의 "확인 필요" 목록 몫)

## 못 할 때

- 검증할 항목이 없으면 "대상 없음" (`status: empty`)
- 반려 건은 `flags[].type: 반려`

## 금지

- 실데이터 커밋 금지 — 테스트는 `sample_data/` 가짜 데이터로만 한다
