# 검증 1 받는 재료 견본 (input-sample)

> verify1이 받는 것은 **가공(refine)의 산출물** — 가맹점이 정규화되고 카테고리가 채워진 거래 표(엑셀 .xlsx)다.
>
> 아래 값은 [collect/result.csv](../collect/result.csv)(하나카드 더미 데이터 기반)의 행에 가공 단계가 붙일 `category`·`refine_status`를 더해 **가정으로 채운 견본**이다 — 실데이터 아님. 가공 칸의 견본이 확정되면 이 문서를 그쪽에 맞춰 갱신한다.

## 컬럼

수집이 만든 컬럼([collect/stub.md](../collect/stub.md))을 그대로 이어받고, 가공이 두 개를 더한다.

| 컬럼 | 설명 | 채우는 단계 |
|---|---|---|
| `transaction_id` | 거래 고유 번호 (`tx_{YYMMDD}_{순번}`) | 수집 |
| `date` | 결제일 | 수집 |
| `expense` | 지출 금액 (양수) | 수집 |
| `income` | 수익 금액 (양수) | 수집 |
| `merchant` | 가맹점명 — **PG사 표기는 가공이 정규화** | 수집 → 가공 |
| `payment_method` | 카드·현금 등 | 수집 |
| `payer` | 결제수단 명의 | 수집 |
| `memo` | 부가 정보 | 수집·가공 |
| `source_type` | `receipt` / `card_excel` / `manual` | 수집 |
| `collect_status` | `대기` / `확인됨` / `확인 필요` | 수집 |
| **`category`** | **[categories.md](../docs/categories.md) 체계의 카테고리 — 이 칸이 판정하는 대상** | **가공** |
| **`refine_status`** | **`확인됨` / `확인 필요` (분류 불가 건)** | **가공** |

## 견본 데이터

`sample_data/hana_card/2026-02_하나카드_이용내역서.csv` 기반. 판정 결과가 갈리도록 정상·불일치·분류불가를 섞었다.

| transaction_id | date | expense | merchant | payment_method | payer | category | refine_status |
|---|---|---:|---|---|---|---|---|
| `tx_260202_01` | 2026-02-02 | 67,302 | 쿠팡 | 하나카드 | 본인 | 소모품·비품 | 확인됨 |
| `tx_260203_01` | 2026-02-03 | 15,674 | CGV | 하나카드 | 본인 | 기타 지출 | 확인됨 |
| `tx_260224_01` | 2026-02-24 | 12,819 | 배달의민족 | 하나카드 | 본인 | 식대 | 확인됨 |
| `tx_260226_01` | 2026-02-26 | 7,608 | 스타벅스 강남점 | 하나카드 | 본인 | 카페 | 확인됨 |
| `tx_260207_01` | 2026-02-07 | 114,674 | 무신사 | 하나카드 | 본인 | | 확인 필요 |

각 행이 무엇을 떠보는 견본인지:

| 행 | 노리는 것 |
|---|---|
| `tx_260202_01` · `tx_260203_01` | 체계에 있는 명칭 → **통과** |
| `tx_260224_01` | `식대`는 체계에 없음 (계정과목명을 그대로 씀) → **반려**, `식비` 추정 |
| `tx_260226_01` | `카페`는 체계에 없음 (일부만 씀) → **반려**, `카페·간식` 추정 |
| `tx_260207_01` | 가공이 분류하지 못한 건 → **반려**, 판정 불가 사유 기재 |

## 못 받는 경우

- 파일이 없거나 열리지 않으면 추측해서 만들지 않는다 — 실패 사실을 그대로 보고한다
- 데이터 행이 0건이면 `"확인 대상 없음"`으로 마무리한다 ([stub.md](stub.md) 참고)
