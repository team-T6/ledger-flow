# 가공 산출물 모양 견본 (stub)

> 가공이 내놓는 것은 **가맹점·카테고리가 붙은 거래 표(CSV)** — `refine/result.csv`. 컬럼은 받은 것([input-sample.md](input-sample.md), 거래 표 스키마 v1) 그대로이고, **컬럼을 늘리거나 줄이지 않는다**. 채우는 것은 `결제처`(정규화)와 `카테고리` 둘뿐이다 ([단계 문서](../.claude/agents/refine.md) "내놓는 모양").
>
> 카테고리 명칭은 [categories.md](../docs/categories.md) 확정 체계의 것을 그대로 쓴다 — 통용 표현(`식비`·`카페` 등)을 만들어 쓰면 분류 검증이 반려한다.

## 산출물 규칙

- 받은 행을 지우거나 순서를 바꾸지 않는다 — `transaction_id`가 행 대조 키
- `결제처`: PG사 표기(예: `NHN KCP/김밥천국`)는 실제 가맹점명으로 정규화. PG/플랫폼 단독 표기(예: `네이버페이`)라 실가맹점을 특정할 수 없으면 **원문 그대로 두고** `카테고리`를 `확인 필요`로
- `카테고리`: `결제처`·`구매항목`·`비고`를 함께 근거로 채운다. 분류 불가 건은 임의 배정하지 않고 `확인 필요`
- 별도 상태 컬럼을 덧붙이지 않는다 — 분류 불가는 `카테고리` 값 `확인 필요` 하나로 표현한다

## 산출물 예시

[input-sample.md](input-sample.md) 견본을 가공한 모양. 지면상 일부 컬럼만 보여준다(`원거래통화`·`원거래금액`은 전부 국내 결제라 빈칸이라 생략) — 실제 `result.csv`에는 13개 컬럼이 모두 있어야 한다.

| transaction_id | 날짜 | 금액 | 결제처 | 카테고리 | 구매항목 | 무엇을 보여주나 |
|---|---|---:|---|---|---|---|
| `tx_260209_01` | 2026-02-09 | -23,787 | 교촌치킨 | 식대 | 허니콤보 치킨 | 단일 업종 → 결제처만으로 분류 |
| `tx_260202_01` | 2026-02-02 | -67,302 | 쿠팡 | 기타물품 | 무선 이어폰 | 종합몰 → 구매항목 근거 분류 |
| `tx_260218_02` | 2026-02-18 | -34,431 | 쿠팡 | 확인 필요 | | 종합몰 + 구매항목 빈칸 → 임의 배정 금지 |
| `tx_260228_01` | 2026-02-28 | -15,900 | 김밥천국 | 식대 | 김밥, 라면 | PG 표기 `NHN KCP/김밥천국` → 정규화 |
| `tx_260228_02` | 2026-02-28 | -45,031 | 네이버페이 | 확인 필요 | | PG 단독 표기 → 결제처 원문 유지 + 확인 필요 |

## 처리할 것이 없을 때

- 입력 거래 표의 데이터 행이 0건이면 헤더만 있는 `result.csv`를 내놓고 "처리 대상 없음"을 보고한다 — 빈 파일을 조용히 내놓지 않는다
