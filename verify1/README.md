# 검증 1 (verify1) — 이 칸의 약속

> 담당: 김윤덕 · 분류 관점 검증 · 상태: 초안
> 계약의 정본은 [인터페이스 정의서](../docs/interface-spec.md), 단계 문서(설계+실행 지시의 단일 정본)는 [.claude/agents/verify1.md](../.claude/agents/verify1.md).

## 하는 일

가공(refine)이 붙인 카테고리가 [categories.md](../docs/categories.md)의 회계 계정과목 체계에 맞는지 항목별로 판정한다. 검증 2와 **같은 입력을 동시에** 받는 병렬 구조이고, 이 칸은 **분류 관점**만 본다 (기간·금액은 [verify2/](../verify2/) 몫).

## 받는 것 / 내놓는 것

| | 내용 | 모양 |
|---|---|---|
| 받는 것 | 가맹점·카테고리가 붙은 거래 표 | CSV — [input-sample.md](input-sample.md) |
| 내놓는 것 | 항목마다 통과/반려 + 이유 한 줄 | CSV — [stub.md](stub.md) |

받은 표의 행을 지우거나 순서를 바꾸지 않는다. 판정 열 두 개(`verify1_result`·`verify1_reason`)를 **뒤에 덧붙이는** 방식이다.

## 이 칸의 파일

| 파일 | 무엇 |
|---|---|
| `README.md` | 이 문서 — 칸의 약속 |
| `input-sample.md` | 받는 재료 견본 (가짜 데이터) |
| `stub.md` | 산출물 모양 견본 (가짜 데이터) |
| `result.csv` | 진짜 산출물 — 실행하면 생김. **커밋하지 않는다** |

칸 폴더를 옮기지 않고, 기존 파일을 지우지 않는다. 새 산출물은 견본 옆에 만든다.

## 판정 규칙 (요약)

카테고리 명칭이 [categories.md](../docs/categories.md)에 정의된 것과 **정확히 일치하면 통과, 다르면 반려**한다. 상세는 [단계 문서](../.claude/agents/verify1.md)에 있다.

- 표기만 다른 경우(띄어쓰기·유사어)도 반려하고, 이유 줄에 어느 카테고리로 보이는지 적는다
- 명칭이 체계에 있으면 통과다 — 그 거래에 그 카테고리가 어울리는지까지는 이 칸이 정하지 않는다
- 검증할 항목이 없으면 `"확인 대상 없음"`으로 표시한다. 빈 파일을 조용히 내놓지 않는다

## 지켜야 할 것

- **실데이터를 커밋하지 않는다.** 견본은 [sample_data/](../sample_data/)의 가짜 데이터로만 만든다 (개인 금융정보)
- **문서 먼저, 구현 나중.** 동작을 바꾸려면 [단계 문서](../.claude/agents/verify1.md)를 먼저 고친다. 단계 간 약속이 걸리면 [인터페이스 정의서](../docs/interface-spec.md)를 담당자 합의로 고친다

## 테스트 방법

`sample_data/`의 가짜 데이터로만 테스트한다 (실데이터 사용 금지 — AGENTS.md §8). 견본 파일(`input-sample.md`·`stub.md`)도 이 가짜 데이터 기준으로 만든다.

| 샘플 입력 | 기대 출력 |
|---|---|
| 모든 행의 카테고리가 체계에 있는 표 | 전 행 통과, 반려 0건 |
| 체계에 없는 명칭(예: "식비")이 섞인 표 | 해당 행만 반려 + 추정 카테고리("식대")가 이유에 포함 |
| 카테고리 칸이 빈 행이 섞인 표 | 해당 행 반려 + 판정 불가 사유 |
| 데이터 행이 0건인 표 | "확인 대상 없음" 표시, 빈 파일 아님 |
