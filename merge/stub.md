# 통합 산출물 모양 견본 (stub)

> merge가 내놓는 진짜 산출물은 **엑셀 회계장부**(`result.xlsx`)와 **PDF 결산 리포트**(`result.pdf`) 두 바이너리 파일이다([orchestrator/result.md](../orchestrator/result.md) 참고). 이 문서는 그 두 파일이 실제로 어떤 모양이어야 하는지 마크다운 표로 보여주는 견본이지, 진짜 산출물이 아니다.
>
> 입력 예시는 [verify2/input-sample.md](../verify2/input-sample.md)의 값(거래 표 스키마 v1 기준)을 그대로 가져왔다. verify1 판정은 이 견본을 위해 새로 가정한 값(카테고리가 전부 [categories.md](../docs/categories.md) 체계에 있어 전부 통과)이다 — refine·verify1의 실제 산출물이 아직 없어 이렇게 가정했다. 전부 연습용 가짜 값이며 실데이터 아님.

## 1. 받는 입력 (가정)

가공(refine)이 넘긴 거래 표 5행과, 검증1·검증2의 판정.

| transaction_id | 날짜 | 금액 | 결제처 | 카테고리 | 결제수단 | 결제구분 | verify1_result | verify2_result |
|---|---|---:|---|---|---|---|---|---|
| `tx_260209_01` | 2026-02-09 | -23,787 | 교촌치킨 | 식대 | 하나카드 | 개인결제 | 통과 | 통과 |
| `tx_260213_01` | 2026-02-13 | -85,589 | 이마트 성수점 | 기타물품 | 하나카드 | 개인결제 | 통과 | 통과 |
| `tx_260217_01` | 2026-02-17 | -17,000 | 넷플릭스 | 구독료 | 하나카드 | 개인결제 | 통과 | 통과 |
| `tx_260301_01` | 2026-03-01 | -29,432 | 올리브영 | 기타물품 | 하나카드 | 개인결제 | 통과 | 반려 (대상 월 아님 — 날짜 2026-03-01) |
| `tx_260215_01` | 2026-02-15 | | 교촌치킨 | 식대 | 하나카드 | 개인결제 | 통과 | 반려 (금액 미기입) |

## 2. 처리 — 반려 건 가려내기

verify1·verify2 중 하나라도 반려면 장부에 싣지 않고 "확인 필요" 목록으로 옮긴다 ([단계 문서](../.claude/agents/merge.md) "하는 단계").

| 항목 | 최종 판정 | 사유 |
|---|---|---|
| `tx_260209_01` 교촌치킨 | 장부에 실음 | verify1·verify2 모두 통과 |
| `tx_260213_01` 이마트 성수점 | 장부에 실음 | verify1·verify2 모두 통과 |
| `tx_260217_01` 넷플릭스 | 장부에 실음 | verify1·verify2 모두 통과 |
| `tx_260301_01` 올리브영 | 확인 필요 | verify2 반려 — 대상 월 아님 |
| `tx_260215_01` 교촌치킨 | 확인 필요 | verify2 반려 — 금액 미기입 |

## 3. 엑셀 회계장부 모양 (`result.xlsx`)

거래 표 스키마와 동일 컬럼. 반려 없는 3행만 싣는다.

컬럼은 스키마 v1 그대로이며 지면상 일부만 표시한다 (`원거래통화`·`원거래금액`은 전부 국내 결제라 빈칸).

| transaction_id | 날짜 | 금액 | 결제처 | 카테고리 | 비고 | 결제수단 | 결제구분 |
|---|---|---:|---|---|---|---|---|
| `tx_260209_01` | 2026-02-09 | -23,787 | 교촌치킨 | 식대 | 포인트 적립 476원 | 하나카드 | 개인결제 |
| `tx_260213_01` | 2026-02-13 | -85,589 | 이마트 성수점 | 기타물품 | | 하나카드 | 개인결제 |
| `tx_260217_01` | 2026-02-17 | -17,000 | 넷플릭스 | 구독료 | | 하나카드 | 개인결제 |

## 4. PDF 결산 리포트 모양 (`result.pdf`)

[interface-spec.md 산출물 양식](../docs/interface-spec.md#산출물-양식-초안)의 7개 목차를 위 3행 기준으로 채운 예시.

**1. 결산 개요** — 대상 기간 2026-02, 대상 카드 하나카드(개인결제). 총지출 126,376원 · 총수익 0원 · 순액 -126,376원

**2. 카테고리별 지출**

| 카테고리 | 금액 | 비중 |
|---|---:|---:|
| 기타물품 | 85,589 | 67.7% |
| 식대 | 23,787 | 18.8% |
| 구독료 | 17,000 | 13.5% |

**3. 결제수단별 합계** — 하나카드 126,376원 (100%)

**4. 결제구분별 합계** — 개인결제 126,376원 (100%), 법인결제 0원

**5. 주요 지출 Top 10** — 실은 행이 3건뿐이라 3건만: 이마트 성수점 85,589 · 교촌치킨 23,787 · 넷플릭스 17,000

**6. 해외결제 명세** — 해당 없음 (해외결제 건 없음)

**7. 확인 필요 항목**

| transaction_id | 날짜 | 결제처 | 유형 | 사유 |
|---|---|---|---|---|
| `tx_260301_01` | 2026-03-01 | 올리브영 | 반려 | 대상 월 아님 (verify2) |
| `tx_260215_01` | 2026-02-15 | 교촌치킨 | 반려 | 금액 미기입 (verify2) |

## 5. 지휘에게 보내는 단계 결과 보고

산출물과 별개로 지휘(orchestrator)에게 돌려주는 요약 JSON. 형식은 [인터페이스 정의서](../docs/interface-spec.md)의 "단계 결과 보고"를 따른다. 위 5건 기준:

```json
{
  "stage": "merge",
  "status": "partial",
  "output": ["merge/result.xlsx", "merge/result.pdf"],
  "counts": { "total": 5, "ok": 3, "flagged": 2 },
  "flags": [
    { "row": 4, "type": "확인 필요", "reason": "대상 월 아님 (verify2 반려)" },
    { "row": 5, "type": "확인 필요", "reason": "금액 미기입 (verify2 반려)" }
  ],
  "message": ""
}
```

전 건 통과면 `status`는 `ok`, `flagged`는 0이 된다.

## 6. 앞 단계 결과가 비어 있거나 반려 미해결일 때

빈 산출물을 내놓지 않고, 장부·리포트의 해당 자리에 "미완"과 사유를 함께 적는다 ([단계 문서](../.claude/agents/merge.md) "못 할 때").

```json
{
  "stage": "merge",
  "status": "empty",
  "output": [],
  "counts": { "total": 0, "ok": 0, "flagged": 0 },
  "flags": [],
  "message": "미완 — 앞 단계(가공 또는 검증) 결과 없음"
}
```

## 아직 정하지 못한 것

- 엑셀·PDF 생성에 쓸 라이브러리 ([merge/README.md](README.md) "협의 중 / 남은 과제" 참고)
