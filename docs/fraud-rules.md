# 법인카드 부정 사용 감지 기준

> 상태: 확정 (팀 합의 — 확정 로그는 [인터페이스 정의서](interface-spec.md) "다음 단계"). 검증 3(verify3)이 판정 기준의 정본으로 쓴다.
> 이 문서는 [categories.md](categories.md)와 같은 결 — 기준 추가·삭제·값 변경은 이 문서를 먼저 고치고(spec-first), 검증 3 에이전트가 따른다. 판정은 **실행 시점의 이 파일 기준**이다.

## 적용 범위

- **법인결제 행만** 판정 대상이다 (`결제구분` = `법인결제`). 개인결제 행은 판정 없이 통과 처리한다.
- **부정 사용 감지 토글을 켠 실행에서만** 동작한다 (실행 파라미터 — interface-spec.md 참고). 기본값은 꺼짐.
- 판정 어휘는 `통과` / `확인 요청` — **부정 사용을 단정하지 않는다.** 걸린 건은 반려가 아니라 사용자 확인(중간 확인·확인 필요 목록)으로 넘긴다.

## 감지 기준

| # | 분류 | 기준 | 신호 강도 | 확인 요청 사유 템플릿 |
|---|---|---|---|---|
| F1 | 시간 | 주말(토·일) 결제 | 약 | `주말 결제 (날짜: {값})` |
| F2 | 시간 | 심야 결제 — 22시 - 06시 (결제 시각을 알 수 있는 행만 — 비고·원문에 시각이 없으면 건너뜀) | 중 | `심야 결제 (시각: {값})` |
| F3 | 업종 | 유흥·사행성 키워드 — 아래 "업종 키워드 표" | 강 | `유흥·사행성 업종 의심 (결제처: {값}, 키워드: {값})` |
| F4 | 성격 | 개인성 소비로 보이는 건이 법인결제로 기입 — OTT·게임·개인 쇼핑 등 (카테고리·구매항목·결제처 근거) | 중 | `개인성 소비 의심 (근거: {값})` |
| F5 | 금액 | 동일 가맹점 단시간 연속 결제 — 같은 `결제처`에서 같은 날 2건 이상 (한도 회피성 분할결제 의심) | 강 | `동일 가맹점 연속 결제 {n}건 (결제처: {값})` |
| F6 | 금액 | 단일 건 고액 — 지출 절대값이 임계치 이상 (기본 300,000원 — 초기값, 운영하며 조정) | 약 | `고액 결제 (금액: {값})` |

### 업종 키워드 표 (F3)

`결제처`·`비고`·`구매항목`에 아래 키워드가 포함되면 F3에 해당한다. 키워드 추가·삭제는 이 표를 고친다.

주점 · 호프 · 포차 · 바(bar) · 클럽 · 라운지 · 노래방 · 노래연습장 · 단란 · 유흥 · 룸 · 가라오케 · 마사지 · 안마 · 스파 · 골프장 · 스크린골프 · 카지노 · 복권 · 로또 · 배팅 · 성인

- "바(bar)"처럼 오탐이 쉬운 짧은 키워드는 단어 경계를 확인한다 (예: "바르다김선생"은 해당 없음). 문자열 포함 판정은 일반 코드로, 경계·문맥 판단은 AI가 한다.

## 판정 규칙 (스코어링)

- **강 신호 1개** 또는 **약·중 신호 합쳐 2개 이상** → `확인 요청`.
- 약·중 신호 1개만 → `통과`시키되 `verify3_reason`에 참고 메모를 남긴다 (예: `참고: 주말 결제`).
- 한 행에 여러 기준이 걸리면 사유를 모두 기록한다 (하나만 적고 끝내지 않는다).
- 판정 근거가 부족한 행(시각 미상 등)은 그 기준을 건너뛴 사실을 임의로 메우지 않는다.

## 확인 요청 이후 흐름

- `확인 요청` 건은 검증 단계 직후의 **중간 확인**(웹 실행 경로)에서 사용자에게 사유와 함께 표시된다. 사용자가 "업무 사용 확정"하면 판정이 `통과`·사유 "사용자 확인"으로 갱신되고, 그대로 두면 통합의 "확인 필요" 목록에 실린다 (interface-spec.md 확정 로그 참고).
- 검증 3은 어떤 경우에도 행을 지우거나 금액·분류를 고치지 않는다 — 판정과 사유만 남긴다.
