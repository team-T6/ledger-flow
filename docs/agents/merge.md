# 통합 에이전트 설계

> 담당: 박인혜 · 상태: 초안
> 입출력의 정본은 [인터페이스 정의서](../interface-spec.md) — 여기에는 요약과 링크만 두고, 상세 스키마를 재정의하지 않는다.

## 1. 역할

가공된 거래 표와 검증1·검증2 결과를 모아 엑셀 회계장부 + PDF 결산 리포트(한 묶음)를 만드는, 파이프라인의 마지막 산출 단계.

## 2. 입출력 요약

- 받는 것: 가공된 거래 표(refine 산출물) + 검증1·검증2의 항목별 통과/반려 결과 → 상세는 [인터페이스 정의서](../interface-spec.md) "통합" 행
- 내놓는 것: 엑셀 회계장부 + PDF 결산 리포트 → 상세는 상동 문서 "산출물 양식"

## 3. 내부 처리 절차

1. 가공된 거래 표와 검증1·검증2 결과를 취합한다
2. 검증 반려 건을 가려내 "확인 필요" 목록으로 옮긴다 (재시도 없음)
3. 반려되지 않은 거래로 거래 표 스키마 그대로 엑셀 회계장부를 만든다
4. PDF 결산 리포트를 목차 순서로 만든다 (결산 개요 → 카테고리별 지출 → 결제수단별 합계 → 결제자별 합계 → 주요 지출 Top 10 → 해외결제 명세 → 확인 필요 항목)
5. 앞 단계 결과가 비어 있거나 반려가 남아 있으면 해당 자리에 "미완" 표시 + 사유를 기재한다
6. 지휘(orchestrator)에게 단계 결과 보고(envelope)를 반환한다

## 4. 판단 규칙

(인터페이스 정의서 "단계별 판단할 것"의 내 단계를 구체화 — 무엇을 어떤 기준으로 판단하나, AI 판단이 필요한 곳과 일반 코드로 처리할 곳 구분)

- 판단할 것: 어떤 구성으로 실어야 읽히는지 (엑셀 장부 컬럼 구성, PDF 리포트 목차 구성)
- 판단 기준: [인터페이스 정의서](../interface-spec.md) "산출물 양식" 초안 — 장부는 거래 표 스키마 그대로, PDF는 제안 목차 7개 항목
- 애매할 때 참조: [categories.md](../categories.md) (카테고리 체계, 검토 중)
- 핵심 지시 (이 에이전트에게 시키는 말의 요지): 검증 반려·미완·오류 건은 버리지 말고 "확인 필요" 항목에 실어라

## 5. 오류·예외 처리

- 가공된 거래 표나 검증 결과가 비어 있으면 그 자리에 "미완" 표시 + 사유를 기재하고 나머지는 정상 진행한다
- 검증 반려 건은 재시도하지 않고 곧장 "확인 필요" 목록에 싣는다 (반려 루프 없음 — 인터페이스 정의서 "지휘" 행 참조)
- 취합 대상 자체가 없어 산출이 불가능하면 단계 결과 보고에 `status: failed`로 남긴다

## 6. 사용 도구·의존성

(미정 — 엑셀 생성·PDF 생성에 쓸 라이브러리 확정 필요)

## 7. 테스트 방법

- `sample_data/` 기준 가공된 거래 표 예시 + 검증1·검증2 결과 예시를 넣어 엑셀 장부·PDF 리포트가 정해진 컬럼·목차대로 나오는지 확인한다
- 반려·미완 케이스를 담은 별도 샘플로 "확인 필요" 항목에 제대로 실리는지 확인한다

## 8. 막힌 점

- PDF 리포트 목차·엑셀 장부 컬럼이 아직 "초안" 상태 — 팀 확정 필요
- [categories.md](../categories.md) 카테고리 체계가 검토 중이라 "카테고리별 지출" 집계 방식도 함께 대기
- 검증 결과 파일 형식(CSV vs JSON)이 미정이라 merge 쪽 파싱 방식도 대기
