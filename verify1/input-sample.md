# 검증 1 받는 재료 견본 (input-sample)

> verify1이 받는 것은 **가공(refine)의 산출물** — 가맹점이 정규화되고 카테고리가 채워진 거래 표(CSV)다.
>
> 아래 값은 [collect/result.csv](../collect/result.csv)(하나카드 더미 데이터 기반)의 행에 가공 단계가 붙일 `카테고리`·`refine_status`를 더해 **가정으로 채운 견본**이다 — 실데이터 아님. 가공 칸의 견본이 확정되면 이 문서를 그쪽에 맞춰 갱신한다.
>
> 컬럼명은 [interface-spec.md](../docs/interface-spec.md) "거래 표 스키마" 기준 한글을 쓰고, 단계 내부 필드(`transaction_id`·`source_type`·`collect_status`·`refine_status`)만 영문으로 둔다 — 수집 칸([collect/stub.md](../collect/stub.md))과 같은 규칙이다.

## 컬럼

수집이 만든 컬럼([collect/stub.md](../collect/stub.md), 거래 표 스키마 v1)을 그대로 이어받고 — `카테고리`는 수집이 빈칸으로 넘긴 것을 가공이 채운다 — 가공이 `refine_status` 하나를 더한다.

| 컬럼 | 설명 | 채우는 단계 |
|---|---|---|
| `transaction_id` | 거래 고유 번호 (`tx_{YYMMDD}_{순번}`) — 행 대조의 기준 키 | 수집 |
| 날짜 | 결제일 | 수집 |
| 금액 | 부호로 지출/수익 구분 — 지출 음수, 수익 양수 | 수집 |
| 결제처 | 가맹점명 — **PG사 표기는 가공이 정규화** | 수집 → 가공 |
| **카테고리** | **[categories.md](../docs/categories.md) 체계의 카테고리 — 이 칸이 판정하는 대상** | **가공** |
| 비고 | 부가 정보 | 수집·가공 |
| 결제수단 | 카드사명 등 | 수집 |
| 결제구분 | `개인결제` / `법인결제` | 수집 |
| 원거래통화 | 해외결제면 통화 코드(예: `USD`), 국내는 빈칸 | 수집 |
| 원거래금액 | 해외결제면 원통화 금액, 국내는 빈칸 | 수집 |
| `source_type` | `receipt` / `card_excel` / `manual` | 수집 |
| `collect_status` | `대기` / `확인됨` / `확인 필요` | 수집 |
| 구매항목 | 실제 구매 물품. **`collect_status`가 `확인됨`인 건만 채우고, `확인 필요`는 빈칸** — 결제처만으론(예: 쿠팡·GS25) 뭘 샀는지 알 수 없어 가공의 카테고리 판단을 보완하는 필드 | 수집 |
| **`refine_status`** | **`확인됨` / `확인 필요` (분류 불가 건)** | **가공** |

(`원거래통화`·`원거래금액`은 전부 국내 결제라 빈칸이어서 지면상 생략 — 실제 CSV에는 있어야 한다)

`tx_260203_01`·`tx_260207_01`는 [collect/result.csv](../collect/result.csv)에서 `collect_status`가 `확인 필요`인 실제 건이라 구매항목이 비어 있다 — 다른 값은 실데이터 아님(가정)이지만, 구매항목의 채움·빈칸 구분만은 실제 collect 산출물과 맞췄다.

각 행이 무엇을 떠보는 견본인지:

| 행 | 노리는 것 |
|---|---|
| `tx_260202_01` · `tx_260203_01` | 체계에 있는 명칭(`기타물품`·`기타`) → **통과** |
| `tx_260224_01` | `식비`는 체계에 없음 (통용 표현을 그대로 씀) → **반려**, `식대` 추정 |
| `tx_260226_01` | `카페`는 체계에 없음 (포함 범위 표현을 씀) → **반려**, `식대` 추정 (커피·디저트는 식대 포함 범위) |
| `tx_260207_01` | 가공이 분류하지 못한 건 → **반려**, 판정 불가 사유 기재 |

## 못 받는 경우

- 파일이 없거나 열리지 않으면 추측해서 만들지 않는다 — 실패 사실을 그대로 보고한다
- 데이터 행이 0건이면 `"확인 대상 없음"`으로 마무리한다 ([stub.md](stub.md) 참고)
