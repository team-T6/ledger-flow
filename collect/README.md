# 수집 (collect) — 이 칸의 약속

> 담당: 이승환
> 계약의 정본은 [인터페이스 정의서](../docs/interface-spec.md), 단계 내부 설계는 [설계서](../docs/agents/collect.md), 에이전트에게 시키는 말은 [지시서](../.claude/agents/collect.md).

## 하는 일

카드사 Excel/CSV와 영수증 이미지·결제 문자 캡처를 바탕으로 거래 정보를 선행 수집하고, 카드사 내역으로 검증·보완해 표준 거래 표를 만든다. 파이프라인의 첫 단계이며 결과는 가공(refine) 단계로 넘어간다.

## 받는 것 / 내놓는 것

| | 내용 | 모양 |
|---|---|---|
| 받는 것 | 카드사 Excel/CSV (카드사·법인/개인마다 컬럼이 다를 수 있음) + 영수증 이미지·결제 문자 캡처(OCR 대상) | 카드사 원본은 CSV/Excel, 이미지는 사진 — [input-sample.md](input-sample.md) |
| 내놓는 것 | 표준 거래 표 | CSV 하나 (`result.csv`) — [stub.md](stub.md) |

카테고리 컬럼은 넣지 않는다 — [categories.md](../docs/categories.md)는 가공(refine) 단계 몫이다. 카드사·법인/개인 조합이 늘어도 표준 컬럼 자체는 바뀌지 않는다.

## 이 칸의 파일

| 파일 | 무엇 |
|---|---|
| `README.md` | 이 문서 — 칸의 약속 |
| `input-sample.md` | 받는 재료 견본 (가짜 데이터) |
| `stub.md` | 산출물 모양 견본 (가짜 데이터) |
| `collect.py` | `sample_data/hana_card/`를 표준 거래 표로 정규화하는 스크립트 |
| `result.csv` | 진짜 산출물 — 실행하면 생김. 지금은 더미 데이터 기반이라 팀 확인 후 예외로 커밋. **실데이터로 실행한 파일은 커밋하지 않는다** |

칸 폴더를 옮기지 않고, 기존 파일을 지우지 않는다. 새 산출물은 견본 옆에 만든다.

## 판단 규칙 (요약)

카드사별 컬럼 매핑으로 표준 필드(날짜·금액·가맹점·결제수단·결제자)로 정규화하고, 날짜+금액+결제처+결제수단 기준으로 영수증·카드내역을 매칭한다. 상세는 [설계서 4장](../docs/agents/collect.md)에 있다.

- 매핑 규칙이 없는 낯선 카드사 서식이면 임의로 끼워 맞추지 않고 확인 필요로 표시한다
- 영수증-카드내역 매칭이 불확실하면 반려 대신 review로 남긴다
- 법인/개인카드 구분은 `결제자` 필드로 하고, 애매하면 확인 필요로 남긴다 — "본인" 같은 구체적인 명의는 지어내지 않는다
- 수집할 원본이 없으면 `"수집 대상 없음"`으로 표시한다. 빈 파일을 조용히 내놓지 않는다

## 지켜야 할 것

- **실데이터를 커밋하지 않는다.** 견본은 [sample_data/](../sample_data/)의 가짜 데이터로만 만든다 (개인 금융정보)
- **명세 먼저, 구현 나중.** 동작을 바꾸려면 [설계서](../docs/agents/collect.md)를 먼저 고친다. 단계 간 약속이 걸리면 [인터페이스 정의서](../docs/interface-spec.md)를 담당자 합의로 고친다
