# 렛저 Ledger Flow — 월말결산 에이전트 PRD (Product Requirements Document)

> 상태: v1 — 파이프라인·산출물·브랜딩 확정 사항 반영 (최초 작성 2026-08-05, 확정 이력은 [인터페이스 정의서](interface-spec.md) "다음 단계" 확정 로그가 정본)
> 렛저 Ledger Flow(repo: `ledger-flow`) — 월말결산 비서. 다중 카드 통합 AI 자동 결산 시스템, 멀티 에이전트 파이프라인 팀 프로젝트. 서비스명·브랜드 정본은 [디자인 가이드](design-guide.md) §1

## 1. 문제 정의

개인·법인 명의가 섞인 복수의 카드를 운용하는 순간, 지출 데이터는 카드사별 엑셀·영수증 사진·결제 문자로 파편화된다. 월 결산을 하려면 이 이질적인 원천들을 일일이 내려받고, 옮겨 적고, 분류하고, 대조해야 하며 — 이 절차는 매달 같은 순서로 반복되지만 여전히 사람 손으로 돌아가며, 여기에 월 4 - 5시간이 쓰인다(확정).

문제의 본질은 셋이다.

1. **파편화** — 원천마다 형식이 달라 통합 자체가 수작업이다
2. **반복성** — 동일한 절차가 매달 사람 손으로 재실행된다
3. **불투명성** — 결산이 끝나기 전까지는 지출 현황을 아무도 정확히 모른다

월말결산 에이전트(ledger-flow)는 이 반복 결산을 수집 → 가공 → 검증 → 통합의 멀티 에이전트 파이프라인으로 자동화하고, 사람의 몫은 예외("확인 필요" 건) 처리로 줄인다.

## 2. 목표와 범위

### 1차 산출물 (이번 과정 범위)

**AI 멀티 에이전트 파이프라인**이 카드 결제 원천 데이터를 받아 월 결산 리포트를 자동 생성한다.

- 입력: Google Drive의 카드사 엑셀 + 영수증 사진·결제 문자 캡처(OCR) — 이미지는 Google Drive·Google Photos에서 수집
	- Google Drive 연동 방식 확정(2026-08-31): Claude CLI headless + Drive MCP로 파일을 `uploads/inbox/`로 가져와 웹 업로드와 동일 경로로 처리 — 상세는 인터페이스 정의서 확정 로그. Photos는 계속 미정
- 출력: 엑셀로 정리된 회계장부 + PDF 결산 리포트
- 형태: 파이프라인 실행 (수집 → 가공 → 검증 → 통합, 오케스트레이터가 순서 지휘)
- **웹사이트 (구현됨 — 확장에서 1차 범위로 편입)**: 초대코드 인증 / Google Drive 가져오기(연동 방식은 위 입력 참고) / 결산 진행 현황(진행률·중간 확인) / 결산 서고(보관된 월 열람·거래 내역·재결산) / **분류 기준 설정 메뉴(GNB — [categories.md](categories.md)를 화면에서 편집, 확정)**. 연동 데이터는 로컬에만 두고 저장하지 않음
	- 데모 운용 (확정): 쇼케이스는 GitHub Pages로 상시 공개(`demo` 브랜치의 `web/` 변경 시 자동 배포), 실제 파이프라인 실행 시연은 로컬 서버 + Cloudflare quick tunnel로 한다 — 절차는 `web/README.md` 참고
- **전월 대비 비교 (구현됨 — 확장에서 1차 범위로 편입)**: 월별 보관(`archive/<월>/summary.json`)이 쌓이면 리포트에 전월 대비 증감·월별 추이를 싣는다 — 구성은 [인터페이스 정의서](interface-spec.md) "산출물 양식"

### 확장 (시간 여유 시)

- **챗봇**: 결산 데이터 기반 질의응답 — 특정 결제 찾기("이 결제 언제 했지?"), 집계 질문("편의점에서 얼마 썼지?"), 누락 데이터 확인. 챗봇 캐릭터 비주얼도 이 항목과 함께 열린 상태 (제작은 이미지 생성 AI)

### 범위 제외 (Non-goals)

- 카드사 API 직접 연동(스크래핑) — 원천은 사용자가 Google Drive·Google Photos에 올린 파일로 한정
- PG사→실가맹점 외부 매핑 데이터 도입 — 가공의 결제처 정규화는 견본 기반 규칙 + AI 판단으로 수행 (확정 로그는 인터페이스 정의서 "다음 단계")
- 실시간 처리 — 월 단위 배치 결산이 기본
- 예산 관리·소비 코칭 등 가계부 앱 기능

## 3. 파이프라인 요구사항 (단계별)

| 단계 | 담당 | 역할 | 핵심 요구사항 |
| --- | --- | --- | --- |
| 수집 | 이승환 | 재료를 모아 정리된 모양으로 | Google Drive·Google Photos 연동, 엑셀 파싱, 사진 OCR → 표준 CSV 스키마로 추출 |
| 가공 | 조영진 | 재료를 쓸 수 있는 형태로 | 결제처 정규화 — PG사 결제면 걸러내고 실가맹점명 식별, 카테고리 분류 |
| 분류 검증 | 김윤덕 | 기준 적합성 확인 | 카테고리 분류가 정의된 체계에 맞는지 검증 |
| 기간·금액 검증 | 이지은 | 기준 적합성 확인 | 대상 월 데이터만 포함됐는지, 해외결제 원화 환산이 맞는지, `금액` 기입이 부호 규칙(지출 음수·수익 양수)에 맞는지 검증 |
| 부정 사용 검증 | 김규은 | 법인카드 부정 사용 감지 (토글 옵트인) | 법인결제 행을 부정 사용 감지 기준([fraud-rules.md](fraud-rules.md) 확정)으로 점검 — 단정하지 않고 `확인 요청`으로 사용자 확인에 넘김. 부정 사용 감지 토글을 켠 실행만 동작 |
| 통합 | 박인혜 | 최종 결과물로 묶기 | 검증 통과 데이터로 월 결산 리포트 생성 (카테고리별 비중 등) |
| 지휘 | 김규은 | 순서대로 부르고 마무리 | 오케스트레이터 — 단계 순차 호출, 실패 처리, 최종 마무리 |

- 각 단계는 독립 에이전트로 구현하고, 단계 간 데이터는 **인터페이스 정의서**(별도 문서)의 계약을 따른다.
- **검증은 병렬 실행한다** — 직렬이 아니라 하나의 검증 스테이지 안에 검증기들을 두는 구조. 기본은 분류/기간·금액 검증 둘이고, 부정 사용 감지 토글을 켠 실행은 부정 사용 검증이 같은 스테이지에 추가된다. 전부 같은 가공 결과를 입력으로 받아 각자 검증 리포트를 내고, 통합 전에 리포트를 merge한다. (규칙이 서로 독립이라 순서 의존이 없고, 오류를 한 번에 모아 반려 1회로 처리하기 위함)
- 검증 실패·반려 건은 재시도(반려 루프) 없이 통합의 "확인 필요" 목록으로 리포트에 싣는다 — 오류 보고 방식 확정.
- 웹 실행 경로에서는 결산이 끝나기 전 **중간 확인**으로 사용자가 확인 필요·반려 건을 직접 수정·확정할 수 있다 — 수정된 건은 "사용자 확인" 이력과 함께 장부에 반영되고, 그대로 둔 건만 확인 필요 목록에 남는다 (상세는 인터페이스 정의서 확정 로그·지휘 단계 문서).
- 결산이 끝난 뒤에도 결과 화면과 보관된 월의 상세 화면에서 남은 확인 필요 건을 수정·확정해 **재결산**할 수 있다 — 반영 효력은 중간 확인의 검증 시점 수정과 같고, 통합만 재실행해 산출물을 다시 만든다 (상세는 인터페이스 정의서 확정 로그).

## 4. 산출물 요구사항

최종 산출물은 두 가지다:

- **엑셀 회계장부**: 정제·분류 완료된 전체 거래 내역 — 카드(명의)별 구분, 카테고리 부여 상태
- **PDF 결산 리포트**: 월 단위 요약 — 카테고리별 지출 금액·비중 등
- 컬럼·목차 상세는 [인터페이스 정의서](interface-spec.md) "거래 표 스키마"·"산출물 양식" 참고

## 5. 비기능 요구사항

- **실데이터 보호**: 카드 실거래 데이터·credential은 repo에 커밋하지 않는다(.gitignore 차단 설정 완료, `sample_data/`만 허용). 개발·시연은 샘플 데이터로 한다.
- **로컬 우선**: 연동 계정 정보 등 민감 데이터는 로컬에만 존재하고 저장·전송하지 않는다.
- 기술 스택: Python — 웹 서버는 표준 라이브러리 `http.server`(추가 설치 없음, `orchestrator/server.py`), 산출물 생성은 `openpyxl`·`reportlab`·`pypdf`, 에이전트 호출은 `anthropic` SDK(API 키 없으면 `claude` CLI 로그인 폴백). 단계 에이전트 구성은 `.claude/agents/` 단계 문서가 정본
