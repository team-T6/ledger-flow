> 이 파일이 가공 단계의 **단일 정본**(설계 + 실행 지시)이다. 단계 간 계약의 정본은 [interface-spec.md](../../docs/interface-spec.md) 가공 행 · 분류 체계는 [categories.md](../../docs/categories.md). 담당·상태·테스트 방법·협의 메모는 [refine/README.md](../../refine/README.md). 동작을 바꿀 땐 이 파일을 먼저 고치고(문서 먼저, 구현 나중), 단계 간 약속이 걸리면 interface-spec을 담당자 합의로 고친다.

# 역할

수집(collect)이 만든 표준 거래 내역표(CSV)를 받아, 결제처의 PG사 표기를 실제 가맹점명으로 정규화하고 각 거래에 카테고리를 채운다. 결과는 가맹점·카테고리가 붙은 거래 표(CSV)로, 파이프라인의 가공 단계 산출물이며 검증 1·2 단계로 넘어간다.

# 받는 것

- 표준 형식의 거래 내역표 (CSV) — 수집(collect) 단계의 산출물. 컬럼은 거래 표 스키마를 따르며 `결제처`는 PG사 표기가 섞여 있고 `카테고리`는 비어 있는 상태로 들어온다. 맨 끝 `구매항목`(영수증에서 추출한 구매 물품, 콤마 구분)이 있으면 카테고리 분류 근거로 쓴다 — 영수증이 없거나 확인 전이면 빈칸일 수 있다 (상세는 [interface-spec.md](../../docs/interface-spec.md) "거래 표 스키마")

# 하는 단계

1. 수집 산출물 거래 내역표(CSV)를 읽는다 (거래 표 스키마 기준)
2. `결제처` 컬럼에서 PG사 이름 뒤의 실제 가맹점이 어디인지 판단해 실제 가맹점명으로 정규화한다
3. `결제처`(정규화된 가맹점명)·`구매항목`(구매 물품)·`비고`(부가 정보) 세 값을 함께 근거로 [categories.md](../../docs/categories.md) [지출] 체계의 `카테고리`를 채운다. `구매항목`이 비어 있으면 `결제처`·`비고`만으로 판단한다. `결제구분`이 `개인결제`면 **개인카드 카테고리** 열의 값을, `법인결제`면 **법인카드 카테고리** 열의 값을 쓴다
4. 가맹점 식별 또는 카테고리 분류가 불가한 건은 임의로 끼워 맞추지 않고 `확인 필요`로 표시하고 버리지 않는다 (§ 못 할 때)
5. 거래 표 스키마를 그대로 유지한 채 CSV로 내놓는다 — 컬럼 추가·삭제 없이 `결제처`·`카테고리`만 채운다

# 내놓는 모양

- `refine/result.csv` — 가맹점·카테고리가 붙은 거래 표. **CSV** 형식이며, 거래 표 스키마는 수집 산출물과 동일하게 유지하고 `결제처`를 정규화하고 `카테고리`를 채운 모양 (스키마는 [interface-spec.md](../../docs/interface-spec.md) 기준, 분류 체계는 [categories.md](../../docs/categories.md) 기준)
- 입력 대비 컬럼을 늘리거나 줄이지 않는다 — 채우는 것은 `결제처`(정규화)와 `카테고리`뿐이다 (`구매항목` 등 나머지 컬럼은 그대로 통과시킨다)
- 결과를 만드는 데 코드가 필요하면 그 코드도 refine 폴더 안에 둔다

# 못 할 때

- PG사 뒤 실제 가맹점을 식별할 수 없거나 카테고리 분류가 불가한 건은 임의로 배정하지 않고 `확인 필요`로 표시하고 버리지 않는다
- 입력 거래 표가 비어 있으면 처리 대상 없음으로 표시한다

# 판단 기준

- PG사 이름 뒤의 실제 가맹점이 어디인지 (결제처 정규화)
- 그 거래가 [categories.md](../../docs/categories.md) 체계의 어느 카테고리인지 — 카테고리 분류는 `결제처`·`구매항목`·`비고` 세 값을 함께 근거로 판단한다
- `결제구분`에 따라 참조할 열이 다르다 — `개인결제`는 **개인카드 카테고리** 열, `법인결제`는 **법인카드 카테고리** 열 (categories.md [지출] 표)
- 애매하면 `구매항목`·`비고`의 부가 정보와 카테고리 체계([categories.md](../../docs/categories.md))를 더 본다. `구매항목`이 비어 있으면 `결제처`·`비고`만으로 판단하고, 특정 불가 시 `확인 필요`로 남긴다
- AI 판단 / 일반 코드 구분: 거래 표(CSV) 읽기/쓰기·스키마 유지·이미 알려진 PG사→가맹점 매핑 규칙 적용은 일반 코드로, PG사 표기 뒤 실제 가맹점 추론과 `결제처`·`구매항목`·`비고` 기반 카테고리 분류는 AI 판단으로 처리한다

# 도구 제한

refine/ 폴더 안의 파일은 읽고 쓴다. 그 외 폴더 접근이나 다른 도구 사용은 하지 않는다.

# 결과 확인 (자체 점검)

산출물을 내놓기 전에 아래를 확인하고, 하나라도 아니면 다시 만든다.

- 모양이 위 "내놓는 모양"의 거래 표 CSV와 같은가 (거래 표 스키마 그대로, 컬럼 추가·삭제 없음)
- `결제처`가 실제 가맹점명으로 정규화됐고, `카테고리`가 [categories.md](../../docs/categories.md) 체계로 채워졌는가 — `결제구분`이 `개인결제`면 개인카드 카테고리 열, `법인결제`면 법인카드 카테고리 열의 값인가
- 식별·분류가 불가한 건을 `확인 필요`로 남겼는가 (임의 배정하지 않았는가)

없는 내용을 지어내서 채우지 않는다.
